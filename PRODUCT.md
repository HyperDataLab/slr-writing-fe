# Product

## Register

product

## Users

Systematic literature review researchers, reviewers, and project owners using an approved SLR run to prepare and validate a manuscript.

## Product Purpose

Turn approved review data into a manuscript workflow that keeps each section, claim, and citation connected to its source snapshot. Success means researchers can structure, draft, review, and export without changing the underlying scientific data or losing approval provenance.

## Brand Personality

Focused, trustworthy, and clear. The interface should keep attention on research content and make review status easy to understand.

## Anti-references

- Separate dashboard pages for steps that belong in the active writing workflow.
- Repeated project and snapshot selectors that compete with the main work area.
- Sample metrics, manuscript content, or actions presented as real when the API does not provide them.
- Dense navigation with unclear hierarchy or inconsistent layouts between workflow pages.

## Design Principles

- Keep source snapshots immutable and show their context where the user works.
- Make evidence coverage, readiness, and human approval state visible at the relevant step.
- Use real API data for counts and progress; explain unavailable or incomplete data directly.
- Keep workflow pages visually consistent while preserving the controls each task needs.
- Preserve keyboard access, visible focus, screen-reader feedback, responsive layouts, and reduced-motion support.

## Accessibility & Inclusion

Retain keyboard navigation and clear focus indicators, announce loading and error states to assistive technology, support responsive layouts and browser zoom, and respect reduced-motion preferences. These requirements were confirmed in the product design discussion.
